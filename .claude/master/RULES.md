# Shared rules (AI-Master-Instructions v4.8.0)

Generated by `.claude/master/sync.mjs`; don't edit. A project overrides a rule by id in AGENTS.md "Overrides" and `.ai-master.json`.

## Working style

- **WS-08** Write plainly: short sentences, numbers with units, no filler. When the user is on a phone, give links and taps, not terminal commands, and publish anything they must read as a page with its link. Show HANDOFF's plan map at the start of a session and when asking the owner to approve a PR or a merge; nowhere else.
- **WS-01** Lead with the answer, then the evidence: a link, command output, or a verbatim quote with `path:line`. Mark paraphrase and inference as such, and don't describe a file you haven't opened.
- **WS-02** Ask before building a major system or deciding something that changes the goal. For small forks, pick the reasonable default, say which, and keep going.
- **WS-03** Ask one consequential question at a time, with short options and your recommendation marked. To start a new project or change its direction, use the `brainstorm` skill first; to plan a project, phase or major feature, use the `planning-interview` skill's saved phone forms instead. Keep proposals visibly separate from approved decisions.
- **WS-04** Engage critically. Don't praise ideas; name weaknesses and better alternatives.
- **WS-06** Never invent a mechanism, fact or requirement to make something work. Ask, or label it an assumption. Copy names (tokens, labels, ids, APIs) from the source, never from memory.
- **WS-07** Don't reopen a settled decision without new evidence. Check DECISIONS before proposing a change to one.

## Context and handoff

- **CTX-03** Update HANDOFF at every checkpoint: after each commit, before a large step or an agent fan-out, and whenever the user decides something.
- **CTX-01** At session start read CLAUDE.md, then HANDOFF.md, then the DECISIONS headings (`grep '^## D-'`), not the whole file. Open other docs only for the section the task needs. Grep archives; never read them whole.
- **CTX-02** HANDOFF.md must let a fresh session continue with no chat history: phase, just done, next, open questions, recent decisions. Keep it to 60 lines; move finished entries to `docs/archive/` monthly.
- **CTX-04** Write logs as dated one-line list entries, not wide tables.
- **CTX-05** Near the context limit, start no new work: update HANDOFF, commit, push and tell the user. After a `/compact`, resume from HANDOFF without asking.
- **CTX-06** Keep always-loaded files short. Put detail in skills or linked docs that load only when needed.

## Verification

- **VER-01** Never skip, disable, weaken or delete a test or check to get green.
- **VER-02** Run the project's local checks before every push. Reproduce a CI failure locally before fixing it.
- **VER-03** When filtering command output, keep warning and error markers (`warn`, `ERR`, `FAIL`, `ELIFECYCLE`). An empty filtered result is a failure until proven otherwise.
- **VER-04** A test that passes only on retry is not green. Find the root cause; never widen an assertion or timeout to hide it.
- **VER-05** Before accepting a review finding, run the related tests and check it against DECISIONS. Reject findings that contradict a tested or settled rule.
- **VER-06** For UI work, look at the result (screenshot or render) before calling it done, and measure performance on a production build. Style docs: the `ui-style` skill; mock-ups: the `ui-mockups` skill.
- **VER-07** Done means checks pass, the behaviour is tested end to end where the project can, and docs are updated. Manual or device checks count only with the owner's evidence.
- **VER-08** After any fix pass, re-check the lines the fix added. Fixes introduce defects.
- **VER-09** At the end of a plan phase or milestone, offer an audit with the `audit` skill.

## Reporting

- **REP-01** Say what was measured and what was estimated, and label every estimate. Take every reported number (a count, size, cost, time or odds) from a tool's output in this session, not from memory or arithmetic done in your head.
- **REP-02** Partial is partial. Report what was skipped or failed, with the output, never only the successes.
- **REP-03** A claim that something is absent ("never mentioned", "unused") needs a recorded search: the terms and paths searched.

## Git and branches

- **GIT-01** One branch per unit of work, cut from the latest default branch. Never reuse a merged branch.
- **GIT-02** After a merge, write follow-up notes on the next branch, never the merged one.
- **GIT-03** Never delete an unmerged branch, rewrite shared history or force-push another person's branch without explicit approval.
- **GIT-04** Merge agent branches one at a time and re-run the checks after each.
- **GIT-05** Commit only green states, with a message saying what changed and why.
- **GIT-06** After a crash or restart, check `git status`, `git worktree list` and each worktree's unmerged commits before starting new work.
- **GIT-07** After the owner approves the work, merge when checks are green without waiting for a reminder. Before approval a draft PR is fine; never mark it ready or merge it.

## Delegation and models

- **DEL-01** The main session plans, decides, reviews, commits and merges. Keep in it: design decisions, questions for the user, settled-rule changes, architecture, safety and final review of delegated work.
- **DEL-03** Pick the agent whose description matches the job; the `routing` skill lists measured costs. Open a reader's cited lines before acting on them.
- **DEL-04** A brief is self-contained: goal, exact files, rules, acceptance criteria, commands to run, "do not commit", and a report-length cap. Ask for results inline, not in files.
- **DEL-05** Review every delegated diff before committing and verify every finding before acting on it. Don't redo the work.
- **DEL-06** Run independent delegated tasks in parallel, each in its own git worktree when it writes files. Keep `.claude/worktrees/` out of git, formatters and linters.
- **DEL-07** Adopt a new agent, skill or hook only when it is measured cheaper or equal at the same quality, and record the measurement. Deterministic chores belong in scripts or hooks.
- **DEL-08** Work in the main session by default. Delegate independent work only when it needs restricted tools, is larger than one context, or is a long read or run whose output you won't keep. Keep dependent chains and small tasks in the main session. The `routing` skill has measured costs.

## Safety and permissions

- **SAFE-01** Ask before anything hard to undo, outside the repo or costing money: publishing, spending (estimate the cost first), a new runtime dependency, paid service, API key or backend, licences, personal data, deleting data, production changes, messages to other people. Reversible work (a branch, a scratch file) needs no permission.
- **SAFE-02** Never commit or print secrets, `.env` files or credentials. Leave protected folders the project names (such as `secrets/`) untouched.
- **SAFE-05** Add only code and assets you have the right to use, and record where each asset came from and its licence.

## Sources of truth

- **SRC-01** Every fact has one home. Link to it; never copy it.
- **SRC-02** When sources disagree, the status ledger (STATUS.md or HANDOFF.md) decides. Reload a stale source from the ledger; don't reconcile toward it. The user's current instruction beats every file.
- **SRC-03** Keep project facts out of agent and skill definitions. Agents read facts from the project's files.
- **SRC-04** Record decisions in DECISIONS.md as Status, Decision and Why. Mark ideas Proposed until the user approves them. A change to a settled rule updates DECISIONS in the same change.
- **SRC-05** When a mistake is found, add or bump a one-line LESSONS entry: area, mistake, root cause, rule, count. At a count of 2, also make it a rule. Mark retired entries SUPERSEDED; never delete them.
- **SRC-06** Never hand-edit files synced from AI-Master-Instructions (listed in `.ai-master.lock`). Change the master, or override a rule by id in AGENTS.md.

## CI budget

- **CI-02** Actions minutes and concurrent jobs are shared by every repo on the account, and CI confirms reviewable work. Open the PR when the work is reviewable and push at reviewable checkpoints. Don't trigger full or manual runs for trivial changes. Every push to a PR branch runs CI, and cancelled runs still bill.
- **CI-03** If a run can't start or fails with a billing, quota, spending-limit or runner-provisioning message: stop and report the exact message. Don't re-run, push empty commits, or close and reopen the PR. (never override)
- **CI-05** Deploy to production only from the default branch, with branch previews off, and merge when a change is done, not to preview it. Deploys and migrations queue and are never cancelled or re-run without reading the log. After a deploy, check the deployed commit equals the merge commit.
- **CI-06** Every workflow job has `timeout-minutes`, least-privilege `permissions` and per-ref concurrency, and runs on PRs and the default branch only. PR jobs skip draft PRs and run when one is marked ready. Change workflows with the `efficient-github-actions` skill.
- **CI-07** After pushing to a PR or marking it ready, schedule your own check of its CI a few minutes later (in cloud sessions, `send_later`) and read the check runs. Never wait for a CI notice or tell the user one will come.

## Game

- **GAME-01** All randomness comes from seeded generators and engine time is injected; the engine never reads `Math.random` or the clock. A run's seed and rules version make it replayable.
- **GAME-02** Game rules live in one engine package with one simulation function for preview and commit. The UI shows results and never recomputes a rule.
- **GAME-03** AI-generated text describes outcomes the deterministic code already decided; it never changes stats, rewards, inventory or progression. Every AI surface has a template fallback.
- **GAME-04** New content is a data entry, not an engine special case. Make consequences visible to the player (a log line, an inspector field).
- **GAME-05** Saves carry a version, older saves upgrade on load, and an unreadable save is never silently overwritten.
- **GAME-06** Keep one determinism test (same seed, same result) rather than batteries of seeds. "Fun" passes only on the owner's recorded playtest findings.
- **GAME-07** Prefer mechanics whose parts reinforce each other. Reject ideas that feel gamey, convenient or bolted on.
